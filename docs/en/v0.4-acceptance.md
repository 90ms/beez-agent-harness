evidence. It is a release-preparation record, not authority to tag, publish,
create a GitHub Release, or deploy.

## Public surface checklist

- Skills: router; spec, plan, implement, verify, review; debug, migrate,
  security, release, performance, GitHub.
- Adapter commands: `init`, `doctor`, `update`, full run lifecycle including
  `checkpoint`, three verification selectors, `version`, and help.
- Configuration fields: `schemaVersion`, `commands`, `verification.required`,
  `verification.profiles`, `verification.timeoutMs`, and `boundaries`.
- Evidence fields: repository/config identity, workflow route, selected profile,
  command results, checkpoints, artifact path/digest, timestamps, and terminal
  state.
- Ownership: Harness-managed, project-owned, operational, shared root guidance,
  and repository-governance surfaces.

## Final local gate

Run from a clean release-preparation branch:

```bash
npm run check
npm run validate
npm run evaluate
npm test
npm pack --dry-run
node scripts/check-release.mjs v0.4.0
```

Before tagging, merge the reviewed commit to `main`, fetch it, and run:

```bash
git fetch origin main
node scripts/check-release-ancestry.mjs HEAD origin/main
```

The branch HEAD is intentionally not release-eligible before merge. Regression
tests independently prove that main-history commits pass and side-branch
commits fail.

## External controls and unresolved actions

For the canonical repository during v0.4 preparation:

- Dependency graph/alerts are enabled so pull request dependency review runs.
- The `npm` Environment exists, but required-reviewer policy remains an
  administrator decision based on the maintainer model.
- Recommended `main` and `v*` rulesets are documented but are not created by
  repository files; an administrator must apply and audit them.
- npm Trusted Publisher configuration must match `release.yml` and the `npm`
  Environment before publication.
- No v0.4 tag, npm publication, GitHub Release, or deployment is part of this
  integration change.

These external controls do not block code and documentation readiness. They do
block a safe publication claim until an authorized maintainer confirms them.
