# v0.4 인수 기준과 릴리스 준비 상태

[한국어](v0.4-acceptance.md) | [English](../en/v0.4-acceptance.md)

이 문서는 v0.4 공개 계약을 구현과 재현 가능한 증거에 연결합니다. 릴리스
준비 기록이며 tag, publish, GitHub Release, deploy 권한을 주지 않습니다.

## 공개 표면 checklist

- Skill: router; spec, plan, implement, verify, review; debug, migrate,
  security, release, performance, GitHub
- Adapter 명령: `init`, `doctor`, `update`, `checkpoint`를 포함한 전체 run
  lifecycle, 세 verify selector, `version`, help
- 설정 field: `schemaVersion`, `commands`, `verification.required`,
  `verification.profiles`, `verification.timeoutMs`, `boundaries`
- 증거 field: 저장소/설정 identity, workflow route, 선택 profile, 명령 결과,
  checkpoint, artifact path/digest, timestamp, terminal state
- 소유권: Harness 관리, 프로젝트 소유, 운영 상태, shared root 안내,
  repository governance

## 최종 로컬 gate

깨끗한 release 준비 branch에서 실행합니다.

```bash
npm run check
npm run validate
npm run evaluate
npm test
npm pack --dry-run
node scripts/check-release.mjs v0.4.0
```

Tag 전에 review된 commit을 `main`에 merge하고 fetch한 뒤 실행합니다.

```bash
git fetch origin main
node scripts/check-release-ancestry.mjs HEAD origin/main
```

Branch HEAD는 merge 전에는 의도적으로 release 대상이 아닙니다. Regression test가
main history commit의 통과와 side branch commit의 실패를 별도로 증명합니다.

## 외부 control과 남은 작업

v0.4 준비 시 canonical repository 상태는 다음과 같습니다.

- Dependency graph/alerts가 활성화되어 PR dependency review가 동작합니다.
- `npm` Environment는 있지만 required-reviewer policy는 maintainer 구성에 따른
  관리자 결정으로 남아 있습니다.
- 권장 `main`, `v*` ruleset은 문서화했지만 저장소 파일만으로 생성되지 않으며
  관리자가 적용하고 audit해야 합니다.
- 게시 전 npm Trusted Publisher가 `release.yml`과 `npm` Environment에 정확히
  맞는지 확인해야 합니다.
- 이 integration change는 v0.4 tag, npm 게시, GitHub Release, deploy를 포함하지
  않습니다.

이 외부 control은 코드와 문서 준비 완료를 막지 않지만, 권한 있는 maintainer가
확인하기 전에는 안전한 게시 완료를 주장할 수 없습니다.
